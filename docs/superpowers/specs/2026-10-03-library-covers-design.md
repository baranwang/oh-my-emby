## 2026-10-03 视觉修订

以用户随后附上的参考图为准：保留左侧纯色背景、右侧三列倾斜海报，媒体库名称在左侧文字区域水平和垂直居中，只显示这一行文字，不绘制副标题。使用系统字体，长名称自适应缩小和字素省略。模板版本为 `rotated-title-v5`；此前全画幅海报 `centered-posters-v2` 是对用户意图的错误理解，已撤回。生成、鉴权、上传和持久化流程沿用原设计。

封面摘要同时比较模板版本；旧模板图片保留至下一次管理员访问时替换成功。清单中的副标题字段保留接口兼容，前端不再用于绘制。

## 目标和已确认方向

为虚拟电影库和剧集库生成入口封面，Dashboard 和 Emby 客户端读取同一份持久化图片。用户已选择库内海报拼图、浏览器生成并上传后端保存，并同意使用 Satori + Canvas。用户明确要求使用生成设备的系统字体，不下载封面专用字体。视觉参考来自 [MoviePilot medialibcovers](https://github.com/baranwang/MoviePilot-Plugins/tree/main/plugins.v2/medialibcovers)。

Workers 服务端不执行图片合成，不增加图片渲染 WASM、Sharp 或独立渲染服务。后台没有浏览器时不会生成或刷新；管理员访问媒体库页面触发自动补齐，已有图片可独立供 Emby 使用。

以下尺寸、预算、自动刷新规则和副标题默认值是本设计提出的第一版默认值，待用户审核。

## 视觉模板

以参考插件的 `cover_style.py` 实际布局为主要依据，`template.pen` 用于确认视觉意图。两者在坐标、间距和旋转约定上有差异，不宣称逐像素复刻。

- 16:9，输出 1920 × 1080；以 320 × 180 的逻辑尺寸缩放六倍。
- 右侧三列、每列三张 2:3 海报，圆角和紧密间距；左右列向下错位。
- 保留参考图倾斜方向。Pillow 的旋转方向与 CSS 旋转方向不同，不能直接照搬角度符号；以参考插件输出的视觉效果校验。
- 主标题放在左侧，以媒体库名称为内容；副标题默认电影库为 `Movies`，剧集库为 `TV Series`。第一版不增加自动翻译或自定义副标题配置。
- 按用户最新要求，从排版前的 1 号海报（第一张成功解码的素材）缩小到 100×100 采样；`315426987` 仅决定海报位置，不影响取色素材，按饱和度（低于 0.05 跳过）加权进行圆周色相平均。按 Python 的 HLS→RGB 转换为 HSL(h, 32%, 32%) 背景色，RGB 通道取整数下界；全灰回退到色相 0（红色）。浏览器使用高质量缩放，允许与 Pillow LANCZOS 存在采样差异。
- 保留由透明到 20% 黑色的纵向背景遮罩及白色标题。长标题在限定文字区域内缩小，必要时截断，保证不挤入海报区。
- 采用参考插件的九宫格海报顺序 `315426987`；不足九张时循环补齐，而非随机复制。

仅移植视觉和排版思路，不复制 MoviePilot 的调度、文件目录、上游写回或服务器管理逻辑。生成的封面只写入 OhMyEmby。

## 前端生成边界

新增独立封面模块，拆分为素材准备、Satori JSX 图形模板、Canvas 栅格化与文字绘制、生成协调四个职责。

1. 从后端取得经过授权和来源过滤的海报清单及生成凭据。
2. 从 Dashboard 同源接口读取海报字节；不得将外站重定向地址直接交给 Canvas。
3. 浏览器解码后将海报缩小到目标绘制尺寸，并转换为嵌入 SVG 的 data URL。单图失败可跳过；零张成功时结束本次生成并保留旧封面或占位图。
4. 使用 Satori 将只有海报、背景和遮罩的 JSX 模板转为 SVG；SVG 内嵌图片，不包含文字，传入空字体列表。
5. 将 SVG Blob 加载为图像后绘制到 Canvas，使用系统字体叠加主标题和副标题，再以 `toBlob` 输出 JPEG。释放临时 object URL 和解码图像。
6. 上传图片，成功后更新媒体库查询缓存。失败不隐藏媒体库列表或阻止保存媒体库配置。

Satori 和生成代码使用动态加载，与常规页面入口分包。第一版在主线程串行生成，每次仅处理一个媒体库，给界面留下更新进度的机会。不预先引入 Web Worker；只有真实浏览器验证发现明显卡顿才调整执行位置。

Satori 不能直接访问用户系统字体，因此所有文字都由 Canvas `fillText` 绘制。中英文使用同一套系统字体栈，以 `system-ui` 开头，再包含 PingFang SC、Microsoft YaHei 和 `sans-serif` 等本地回退；不得引用 Dashboard 的 Lexend 网络字体或下载参考插件字体。主标题使用 700 字重，副标题使用 600 字重；浏览器按本机字体和字形覆盖执行回退。字体栈明确写入封面生成模块，不从页面 CSS 间接继承。

使用同一 Canvas 字体设置进行 `measureText` 与绘制，按实际测量结果缩小和截断长标题，避免假定中英文字符等宽。不同操作系统生成的文字外观允许有差异；上传后图片已固化，所有客户端读取相同结果，不因阅读设备再次换字体。

## 自动生成和刷新

管理员打开媒体库列表时，在列表加载完成后串行补齐启用库的缺失或配置过期封面。已存在且配置未变化的图片不重新选图；新增影片本身不触发刷新。详情页提供封面预览和“重新生成”按钮，生成时显示状态与失败后的重试入口。

库名、媒体类型、启用来源绑定变化后将封面标记为过期，继续展示旧封面至替换成功。被停用或移除的来源不进入新的素材清单。关闭页面或中断请求时保留旧图片，之后访问可以重试。每次页面访问只自动尝试每个库一次，不在失败后无限循环。

两个标签页可以同时准备封面；后端以生成时读取的当前封面版本执行条件写入，第一个有效上传成功后，旧版本上传返回冲突，前端重新读取已经保存的封面。

## 后端职责和接口

新增 `LibraryCoverService`，负责选图清单、生成凭据、上传验证和读取。图片处理只在浏览器执行。数据库访问沿用 Effect 服务与平台仓储适配模式。

Dashboard 接口全部要求现有管理员会话；生成清单和上传沿用现有写请求 Origin 校验。接口相对于 `/api/dashboard`：

- `POST /libraries/:id/cover/prepare`：创建生成清单，返回候选标识、同源素材路径、标题、模板版本、配置摘要、预期旧封面版本和不透明生成 token。
- `GET /libraries/:id/cover/assets/:token/:index`：验证 token 与索引后，使用已注册来源获取图片字节，不接受任意 URL。复用上游认证、连接选择、UA 策略、超时和现有图片资源限制；成功响应不得重定向到外站。
- `PUT /libraries/:id/cover`：以原始 `image/jpeg` 请求体和生成 token 上传图片，返回封面摘要。
- `GET /libraries/:id/cover`：读取持久化图片，支持 GET/HEAD、ETag 和条件请求。

生成清单存储在数据库中，每库最多保留四份，有效期十分钟，token 使用随机 UUID。清单记录配置摘要、来源 generation、候选及生成前的封面版本。创建时清理过期记录，删除媒体库时一并删除。

海报候选优先来自已有有效聚合目录；不足时执行有限目录查询。候选只允许属于该虚拟库启用来源且仍然有效的 Movie 或 Series，剧集不使用单集海报。按规范条目 ID 去重，稳定排序。每个来源至多查询一页、最多二十个条目，总计最多两百条；停止于取得最多十八张海报候选，前端最多选取九张成功解码的图片。预算耗尽只使用已经证实的结果，不后台遍历媒体库。

上传时重新校验库存在、配置摘要、来源 generation、token 有效期和预期旧封面版本。请求体上限 500 KiB；前端从约 0.85 的 JPEG 质量开始逐级降低至 0.5，仍超限则明确失败，不提交超限数据。服务端检查 JPEG 签名和有预算的帧头解析，要求尺寸正好 1920 × 1080；不能仅信任 Content-Type 或前端传入尺寸，也不执行完整像素解码。

封面版本使用 JPEG 字节的 SHA-256 摘要。模板版本和配置摘要另行保存，避免将素材 URL 或上游凭据暴露在版本值中。成功上传后消费该清单；冲突、来源变化和失败都不得覆盖现有图片。

## 持久化与缓存

新增 `library_covers` 表，一库一张图片，存放 library ID、JPEG BLOB、content type、尺寸、内容摘要、模板版本、配置摘要和更新时间。另建生成清单表，记录上述临时凭据与选图信息。Bun 使用 SQLite，Workers 使用 D1，两个平台共享迁移和业务语义。

封面字节不进入库列表 JSON；`VirtualLibraryView` 增加可选封面摘要，包含版本、尺寸和是否过期。媒体库删除同时清理两张表的相关记录。

现有 ResourceCache 可缓存持久化图片的读取结果，但不是唯一副本。缓存未命中从数据库恢复，不需要浏览器再次渲染。带 revision 的图片缓存键区分内容，响应保留鉴权边界，不因缓存绕过媒体库可见性检查。

## Emby 与 Dashboard 展示

在所有已有虚拟库 DTO 路径中一致返回 `ImageTags.Primary`，值为封面版本，并提供 `PrimaryImageAspectRatio=16/9`。没有持久化封面时不声明图片 tag，Dashboard 显示占位图。

`/Items/{libraryId}/Images/Primary` 及 `/emby` 前缀等价路径，在进入现有条目图片解析前识别虚拟库并读取其封面。只提供 index 0 的 Primary；其他图片类型或索引保持未找到语义。保留现有 Emby 鉴权，停用库不通过图片路径泄漏。

支持 GET、HEAD、内容长度、ETag、条件读取。带旧 tag 的请求不能给新内容附加永久不变的旧版本缓存键；返回当前内容时使用可重新验证策略。以实际客户端验证缓存刷新行为。

Dashboard 列表展示横向封面，详情页展示同一图片与生成状态。图片通过 cookie 路径允许的 Dashboard 同源接口读取，不把上游 api_key 放入页面或生成 SVG。新增 UI 文案沿用项目国际化约定。

## 验证与验收

- 用固定样例海报在真实浏览器渲染，并查看输出图片，验证倾斜方向、错位列、裁剪、标题、渐变、中文和超长名称；不能只检查 SVG 字符串。验证无文字的 Satori 模板可使用空字体列表，Canvas 按系统字体绘制，生成模块不请求任何字体资源。
- 验证九张、不足九张、部分失败和零张素材；验证失败后保留旧封面、生成串行及重试不会无限触发。
- 两个平台验证图片上传、数据库重新打开后的持久性、上传大小和 JPEG 尺寸校验、过期 token、版本冲突、来源变更、删除清理及素材接口授权范围。
- 验证 Dashboard 读取及所有虚拟库 Emby DTO 的 tag 一致；图片 GET/HEAD、ETag、缺失图片和停用媒体库行为正确。
- 运行项目要求的 typecheck、相关测试、build 与 Workers 测试，检查生成依赖只进入 Dashboard 静态资源，不扩大 Workers 图片计算职责。

## 第一版范围之外

不实现后台无人值守自动更新、自定义模板编辑器、副标题配置、AI 翻译、上游 Emby 封面写回、R2 存储、全库扫描或多种封面风格。
